# The biggest change I'd make to your study method

Don't try to **finish more problems**.

Try to **remember more patterns**.

For every problem you solve, write only 4 things:

```text
Problem:
Pattern:
Key observation:
My mistake:
```

For example:

```text
Problem: Maximum consecutive ones

Pattern: Running count

Key observation:
Reset count when we see 0.

My mistake:
Initially didn't understand ++run.
```

Another:

```text
Problem: Sort 0,1,2

Pattern: Dutch National Flag / 3 pointers

Key observation:
[0 ... low-1] = 0
[low ... mid-1] = 1
[high+1 ... n-1] = 2

My mistake:
Didn't know Java swap needs array + indexes.
```

This is much more valuable than copying the entire solution into notes.

# And I want you to change one thing about solutions

Right now, I think you are sometimes doing:

```text
Watch video
↓
Understand
↓
Code along
↓
Feels like I solved it
↓
Move on
```

That's dangerous because **recognition feels like knowledge**.

Instead:

```text
Read problem
↓
Try yourself for 15–20 min
↓
Write your approach even if wrong
↓
Take a SMALL hint
↓
Try again
↓
If completely stuck → see solution
↓
Close solution
↓
Code it yourself from memory
↓
Revisit after 2–3 days
```

That last step is extremely important.

# And here's something I really want you to stop doing

Don't judge your DSA progress by:

> “Can I solve today's problem?”

Judge it by:

> “Could I solve something today that I couldn't understand two months ago?”

Because DSA has a very weird learning curve.

You'll spend:

```text
20 minutes → nothing
30 minutes → nothing
45 minutes → nothing
```

Then suddenly one day you see:

```text
"Wait... this is just two pointers."
```

That recognition is what you're training.
